# 최우선 작업 기록 — 자동 색인·화면 흔들림 안정화

기록일: 2026-08-03
우선순위: 미리보기 형식 확장보다 먼저 처리

## 추가 미리보기 요구사항

아래 형식은 모두 **원본 레이아웃이 아닌 텍스트·표 중심 미리보기**로 제공한다.

- `.xls`: Kordoc XLS 파서를 연결해 시트·셀·표를 미리보기한다.
- HWP 3.x: Kordoc의 기존 `.hwp` 지원을 사용하고 자동 감지·미리보기를 검증한다.
- `.pptx`: 슬라이드별 제목·본문·목록을 추출한다.
- `.ppt`: 로컬 변환기 또는 호환 파서로 텍스트를 추출한다.
- `.doc`: 문단·표 텍스트를 추출한다.
- `.odt`: 문단·제목·표를 추출한다.
- `.ods`: 시트·셀·표를 추출한다.
- `.rtf`: 서식을 제거한 본문 텍스트를 미리보기한다.

## 문제

- 등록 폴더를 감시하는 자동 색인 자체는 필요한 기능이지만, 파일 변경이 없는데도 하단 상태가 반복해서 `색인 중`으로 바뀌고 화면이 흔들리는 현상이 발생한다.
- 현재 폴더 등록 흐름에서 백엔드 활성화와 화면 코드가 색인을 각각 시작할 가능성이 있어 초기 작업 중복 여부를 제거해야 한다.
- 파일 감시용 증분 색인 작업까지 일반 색인 진행 UI에 표시되어 footer가 나타났다 사라지며 레이아웃이 이동한다.

## 수정 목표

1. 폴더 등록 시 색인 시작 지점을 하나로 통합해 중복 작업을 방지한다.
2. 파일 감시·주기적 reconcile 작업은 내부적으로 처리하되 사용자가 직접 시작한 색인만 완료 보고서와 진행 UI에 표시한다.
3. 자동 색인 상태가 바뀌어도 footer 높이가 변하지 않도록 고정 레이아웃으로 변경한다.
4. 동일한 파일 메타데이터의 반복 이벤트를 건너뛰고, 500ms debounce 및 임시·동기화 파일 이벤트를 안전하게 억제한다.
5. 자동 감시가 실제로 필요한 변경만 처리하는지 CPU·디스크 사용량과 이벤트 빈도를 검증한다.

## 확인 항목

- 앱 시작 직후 전체 색인이 무조건 재실행되지 않는지 확인한다. 단, 중단된 작업 복구와 등록 폴더 변경 감지는 정상 동작해야 한다.
- 파일을 한 번 저장했을 때 증분 색인이 한 번만 실행되는지 확인한다.
- 아무 파일도 변경하지 않은 상태에서 하단 상태가 `색인 중`으로 반복 전환되지 않는지 확인한다.
- 색인 중에도 상단 메뉴·중앙 영역·오른쪽 미리보기의 위치가 흔들리지 않는지 확인한다.
- 수정 후 Windows 포터블 실행 파일에서 동일 시나리오를 재검증한다.

# EveryFile 추가 파일 형식 미리보기 작업 지침서

작성일: 2026-08-02
대상 저장소: `L:\codex-L\EveryFile`
목표: 파일을 선택했을 때 원본 레이아웃을 재현하지 못하는 형식도 오른쪽 창에서 읽을 수 있는 텍스트·표 미리보기를 제공한다.

## 1. 작업 범위

### 1.1 현재 유지할 기능

- 이미지 직접 미리보기: `png`, `jpg`, `jpeg`, `webp`, `bmp`, `gif`, `tif`, `tiff`, `svg`
- 문서 텍스트 미리보기: `txt`, `md`, `markdown`, `hwp`, `hwpx`, `hml`, `hwpml`, `pdf`, `docx`, `xlsx`
- 원본 레이아웃 미리보기: `hwp`, `hwpx`, `pdf`
- 문서 내 검색, 검색어 강조, 표의 가로 스크롤, 파일 열기·파일 위치 열기

### 1.2 이번에 추가·검증할 형식

| 형식 | 확장자 | 목표 미리보기 | 원본 레이아웃 |
|---|---|---|---|
| 구형 Excel | `.xls` | 시트·셀·표·날짜를 텍스트/표로 표시 | 범위 밖 |
| HWP 3.x | `.hwp`(매직바이트로 자동 판별) | 본문·표·머리말·각주 텍스트 | 범위 밖 |
| PowerPoint | `.pptx` | 슬라이드 순서, 제목, 본문, 목록, 표 텍스트 | 범위 밖 |
| 구형 PowerPoint | `.ppt` | 가능한 범위의 슬라이드 텍스트 | 범위 밖 |
| 구형 Word | `.doc` | 문단·표 텍스트 | 범위 밖 |
| OpenDocument Text | `.odt` | 제목·문단·목록·표 텍스트 | 범위 밖 |
| OpenDocument Spreadsheet | `.ods` | 시트·셀·표 텍스트 | 범위 밖 |
| Rich Text Format | `.rtf` | 서식 제거 후 문단·텍스트 | 범위 밖 |

이번 작업은 **읽기 전용 텍스트/표 미리보기**만 다룬다. 새 형식의 원본 레이아웃 렌더링, 편집, 저장, OCR은 별도 작업으로 분리한다.

## 2. 구현 원칙

1. 모든 파싱은 PC 내부에서 수행한다. 파일 내용을 외부 API, 클라우드, 원격 변환 서비스로 보내지 않는다.
2. 사용자가 Microsoft Office나 한컴오피스를 설치하지 않아도 동작해야 한다. Office COM 호출을 유일한 경로로 사용하지 않는다.
3. 파서는 기존 `ParsedDocument` 계약을 반환한다.
   - `title`
   - `markdown`
   - `plainText`
   - `blocks`
   - `metadata`
   - `warnings`
4. 파싱 실패가 색인 전체를 중단시키면 안 된다. 해당 파일만 `UNSUPPORTED`, `DAMAGED`, `ENCRYPTED`, `TOO_LARGE` 등의 구조화된 실패로 기록하고 다른 파일을 계속 처리한다.
5. 매크로, 외부 링크, OLE 개체, 포함 스크립트는 실행하지 않는다. 문서 안의 텍스트와 안전한 표 구조만 추출한다.
6. ZIP/XML 기반 형식은 압축 해제 폭탄, XXE, 비정상적으로 큰 행·열·슬라이드 수를 제한한다.
7. 미리보기에는 원본 파일의 전체 내용을 무제한으로 넣지 않는다. 기존 미리보기 문자·블록 예산과 파일 크기 제한을 재사용한다.

## 3. 구현 순서

### 단계 A — 현황 고정 및 샘플 준비

- `src/features/preview/PreviewPanel.tsx`의 이미지·텍스트·레이아웃 분기를 기준선으로 고정한다.
- `src-tauri/src/indexing/coordinator.rs`의 `candidate_requires_extraction` 확장자 목록을 확인한다.
- 각 확장자별 최소 3개 샘플을 준비한다.
  - 정상 한국어 문서
  - 표 또는 다중 단락이 있는 문서
  - 손상·암호화·빈 문서
- 샘플에는 개인정보와 외부 전송이 필요한 자료를 사용하지 않는다.

### 단계 B — Kordoc 연결 확대

- `.xls`는 Kordoc의 `parseXls` 경로를 사용한다.
- HWP 3.x는 별도 확장자가 없으므로 `.hwp` 파일의 매직바이트 자동 판별 결과가 `hwp3`일 때도 정상적으로 저장되는지 검증한다.
- `sidecar/parser-host/src/kordoc-adapter.ts`의 결과 정규화가 `table`, `heading`, `list`, `paragraph`, `image` 블록을 보존하는지 확인한다.
- `.xls`를 색인 추출 대상에 추가한다. HWP 3.x는 `.hwp`가 이미 대상이면 별도 확장자를 추가하지 않는다.
- XLS/XLSX 표는 시트 이름을 제목 또는 메타데이터로 보존하고, 셀 줄바꿈과 빈 셀을 임의로 합치지 않는다.

### 단계 C — OpenDocument 파서 추가

- `.odt`와 `.ods`는 ZIP/XML을 로컬에서 읽는다.
- XML 네임스페이스를 접두사 이름이 아닌 URI 기준으로 처리한다.
- ODT는 제목·문단·목록·표를 추출한다.
- ODS는 시트 이름·행·열·셀 값을 추출한다.
- 수식은 계산하지 않고 안전한 표시 문자열 또는 원본 수식 문자열로 보존한다.
- 외부 링크와 임베디드 매크로는 무시하고 경고로 기록한다.

### 단계 D — OOXML 프레젠테이션 및 구형 형식

- `.pptx`는 ZIP/XML을 로컬 파싱하여 슬라이드 순서, 제목, 본문, 목록, 표를 블록으로 변환한다.
- 슬라이드 번호를 `pageNumber`에 저장하여 미리보기에서 구분한다.
- `.ppt`와 `.doc`는 포터블 배포에 포함할 수 있는 로컬 파서 또는 변환기를 선정한 후 구현한다.
- 사용자의 Office 설치 여부에 의존하지 않는다.
- 변환기를 번들할 수 없거나 안전하게 파싱할 수 없으면 파일을 조용히 실패시키지 말고 “텍스트 미리보기 미지원” 사유를 표시한다.

### 단계 E — RTF 파서 추가

- `.rtf` 제어어, 유니코드 이스케이프, 문단·탭·표시용 줄바꿈을 안전하게 해석한다.
- 글꼴·색상·페이지 배치는 보존하지 않고 읽을 수 있는 텍스트로 변환한다.
- `\\pict` 이미지와 OLE 개체는 실행하지 않는다. 필요하면 `[첨부 이미지]` 같은 안전한 자리표시자로 남긴다.

### 단계 F — 색인·미리보기·UI 연결

- `candidate_requires_extraction`에 다음을 추가한다: `xls`, `ppt`, `pptx`, `doc`, `odt`, `ods`, `rtf`.
- 파서 사이드카드의 확장자 라우팅과 오류 코드를 추가한다.
- `PreviewPanel`은 새 형식을 문서 텍스트 탭으로 표시한다. 기존 일반 블록 렌더러와 표 렌더러를 재사용한다.
- 원본 레이아웃 탭은 새 형식에 대해 비활성화하거나 “원본 레이아웃 미지원” 안내를 표시한다.
- 파일 선택 직후 탭이 사라지지 않도록 기존 로딩 상태와 동일한 탭 표시 정책을 유지한다.
- 결과가 비어 있을 때는 빈 화면 대신 원인과 `파일 열기` 버튼을 보여준다.
- 확장자 필터 목록에도 실제 지원 상태를 반영한다. 단순히 목록에만 넣고 파싱되지 않는 형식을 지원하는 것처럼 보이게 하지 않는다.

## 4. 형식별 완료 기준

- `.xls`: 2개 이상 시트, 병합 셀, 날짜/숫자, 한국어 셀을 올바른 순서로 표시한다.
- HWP 3.x: 본문과 표가 검색·텍스트 미리보기에 나타나며 HWP 5.x와 혼동되지 않는다.
- `.pptx`: 모든 슬라이드의 텍스트 순서와 표 셀 값이 누락 없이 표시된다.
- `.ppt`: 정상 샘플에서 최소한 슬라이드 텍스트를 표시하고, 실패 시 명확한 안내를 표시한다.
- `.doc`: 문단 순서와 표 텍스트를 표시한다.
- `.odt`: 제목·목록·표 구조를 보존한다.
- `.ods`: 시트별 셀 값을 행/열 순서로 표시한다.
- `.rtf`: 한글, 이모지, 유니코드 이스케이프와 문단 구분을 보존한다.
- 어느 형식도 앱 전체 색인 작업을 멈추거나 UI를 정지시키지 않는다.

## 5. 테스트 계획

### 5.1 파서 단위 테스트

- 정상 파일, 빈 파일, 손상 파일, 암호화 파일, 크기 제한 초과 파일
- 한글·영문·숫자·이모지·혼합 줄바꿈
- 병합 표, 빈 셀, 다중 시트/슬라이드
- 외부 링크·매크로·OLE가 실행되지 않는지 확인

### 5.2 통합 테스트

- 폴더 색인에서 새 확장자가 `indexed` 상태로 저장되는지 확인
- 한 파일 파싱 실패가 나머지 파일의 색인을 방해하지 않는지 확인
- 검색 결과 선택 시 오른쪽 텍스트 미리보기가 열리는지 확인
- 문서 내 찾기와 검색어 강조가 새 형식에서도 작동하는지 확인
- 파일 열기·파일 위치 열기·경로 복사가 기존과 동일하게 작동하는지 확인

### 5.3 배포 테스트

- 개발 환경과 포터블 실행 파일에서 동일한 결과 확인
- 설치 파일에 새 파서·런타임·모델이 누락되지 않았는지 확인
- 터미널 창이 나타나지 않는지 확인
- 인터넷을 차단한 상태에서도 문서 파싱·미리보기가 작동하는지 확인

## 6. 완료 체크리스트

# 최우선 작업 기록 — 자동 색인·화면 흔들림 안정화

기록일: 2026-08-03
우선순위: 미리보기 형식 확장보다 먼저 처리

## 문제

- 등록 폴더를 감시하는 자동 색인 자체는 필요한 기능이지만, 파일 변경이 없는데도 하단 상태가 반복해서 `색인 중`으로 바뀌고 화면이 흔들리는 현상이 발생한다.
- 현재 폴더 등록 흐름에서 백엔드 활성화와 화면 코드가 색인을 각각 시작할 가능성이 있어 초기 작업 중복 여부를 제거해야 한다.
- 파일 감시용 증분 색인 작업까지 일반 색인 진행 UI에 표시되어 footer가 나타났다 사라지며 레이아웃이 이동한다.

## 수정 목표

1. 폴더 등록 시 색인 시작 지점을 하나로 통합해 중복 작업을 방지한다.
2. 파일 감시·주기적 reconcile 작업은 내부적으로 처리하되 사용자가 직접 시작한 색인만 완료 보고서와 진행 UI에 표시한다.
3. 자동 색인 상태가 바뀌어도 footer 높이가 변하지 않도록 고정 레이아웃으로 변경한다.
4. 동일한 파일 메타데이터의 반복 이벤트를 건너뛰고, 500ms debounce 및 임시·동기화 파일 이벤트를 안전하게 억제한다.
5. 자동 감시가 실제로 필요한 변경만 처리하는지 CPU·디스크 사용량과 이벤트 빈도를 검증한다.

## 확인 항목

- 앱 시작 직후 전체 색인이 무조건 재실행되지 않는지 확인한다. 단, 중단된 작업 복구와 등록 폴더 변경 감지는 정상 동작해야 한다.
- 파일을 한 번 저장했을 때 증분 색인이 한 번만 실행되는지 확인한다.
- 아무 파일도 변경하지 않은 상태에서 하단 상태가 `색인 중`으로 반복 전환되지 않는지 확인한다.
- 색인 중에도 상단 메뉴·중앙 영역·오른쪽 미리보기의 위치가 흔들리지 않는지 확인한다.
- 수정 후 Windows 포터블 실행 파일에서 동일 시나리오를 재검증한다.
