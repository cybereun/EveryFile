# EveryFile 업그레이드 UI 목업

## 최신안: 사용자가 제공한 원본 화면 기반

[원본 기반 리뉴얼 목업 열기](everyfile-original-refresh.html)

[기본 화면](원본기반-리뉴얼.png) · [AI 질문 펼친 화면](원본기반-AI질문.png) · [다크 화면](원본기반-다크.png)

제공된 원본 스크린샷을 기준으로 브랜드와 베이지 색감, 폴더·스마트 폴더·최근 검색·북마크, 본문 문맥 중심 검색 결과, 넓은 HWP 문서 뷰어를 유지했습니다. 앞선 목업의 파일 테이블·작은 상세 카드 대신 원본의 문서 검색 작업 흐름을 따릅니다.

주요 변경은 가로로 넘치던 필터의 주요/상세 분리, 필요할 때 펼치는 AI 질문, 검색어와 선택 항목 강조, 정돈한 문서 도구 모음, 목록 수집·본문 분석 상태 분리입니다. 가운데 경계선을 드래그하거나 키보드 좌우 방향키로 미리보기 폭을 조절할 수 있습니다.

검색 모드·확장자·정렬·상세 필터·파일 선택·AI 영역 펼치기·문서 보기 전환·문서 내 찾기·확대·페이지 번호 전환·패널 접기·일시정지·다크 모드를 체험할 수 있습니다. 페이지 전환은 번호만 변경하며 가상 문서를 재사용합니다. 실제 HWP/PDF 파싱, AI 호출, 로그인, 파일 열기·내보내기는 실행하지 않습니다. 문서 표와 내용은 목업용 가상 자료이며 실제 학생 기록이 아닙니다.

Edge에서 1600×1000 및 390×844 화면을 캡처했습니다. 12개 동작 확인, 가로 넘침 검사, 런타임 예외 검사를 통과했습니다. 재검증: `node docs/mockups/verify-mockup.mjs --original`. 추가 설치 없이 L드라이브에 결과와 임시 프로필을 저장했습니다.

## 이전안

[클릭 가능한 목업 열기](everyfile-upgrade.html) — 파일을 브라우저에서 열면 됩니다. 설치나 서버 실행은 필요하지 않습니다.

## 현재 앱과 얼마나 달라지나요?

좌측 폴더 탐색, 중앙 검색 결과, 우측 미리보기라는 기본 배치는 유지합니다. 눈에 보이는 변화는 색감·아이콘·여백·검색창·파일 행·작업 상태 표현입니다. 전혀 다른 사용법을 배우기보다는 기존 구조에서 필요한 기능을 더 쉽게 찾는 방향입니다.

- **기존 색감 유지안:** 현재 코드의 베이지·테라코타 색상을 새 레이아웃에 적용했습니다. 실제 현재 화면을 촬영하거나 그대로 복제한 것은 아닙니다.
- **추천 리디자인:** 밝은 회색·흰색과 청록색 강조를 사용합니다. 파일에 집중할 수 있도록 장식과 시각적 무게를 줄였습니다.
- **다크 모드:** 같은 레이아웃을 어두운 테마로 전환합니다.

## 눌러볼 수 있는 기능

파일명 검색(예: `보고서`), 파일 종류 필터, 이름 정렬, 저장 위치별 목록, 즐겨찾기, 파일 선택과 상세 패널, 목록 밀도, 수집 일시정지·재개, 작업 상세, 저장 위치 안내가 작동합니다. `Ctrl+K`로 검색창에 이동할 수 있습니다.

원본 열기·계정 연결·본문 분석은 실제 실행 대신 동작 설명을 표시합니다. 경로 복사 버튼은 예시임을 명시한 문자열을 복사합니다. 데이터와 수집 건수는 고정 예시이며 실제 성능이나 실제 파일 목록이 아닙니다. 본 목업 자체가 수백만 건을 처리하는 제품 구현은 아닙니다.

## 확인 결과

기존 Edge의 실제 렌더링으로 1440×1000 및 390×844 화면을 확인했습니다. 검색·필터·선택·일시정지·대화상자·저장 위치 전환 등 7개 검사와 가로 넘침 검사를 통과했고 런타임 예외는 없었습니다. `verify-mockup.mjs`는 캡처 재생성 및 동작 확인용 스크립트입니다.

새 패키지를 설치하지 않았습니다. 목업과 캡처, 검증용 브라우저 프로필·임시 파일은 프로젝트의 L드라이브 경로에 저장했습니다. 실제 앱 소스와 실행 중인 수집 작업은 변경하지 않았습니다.
